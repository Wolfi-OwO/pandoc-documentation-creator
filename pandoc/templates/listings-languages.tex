% ########
% Non-Copyable Line Numbers
% ---
% Line numbers should be visible but must NOT end up in the clipboard when a
% reader selects a listing. We tag each gutter number with an empty PDF
% `ActualText` (via accsupp): conforming text extractors then copy the code
% only. `\noncopynumber` is appended to the global `numberstyle` below;
% listings passes the number to it as an argument.
%
% Caveat: ActualText is honored by Acrobat and poppler-based viewers
% (Evince, `pdftotext`), but some embedded viewers (Chrome/PDFium, the VS Code
% preview) ignore it and may still copy the digits.
%
% The macro is defined inside \if...\fi (conditional *text*), not inside the
% brace arguments of \IfFileExists, so its `#1` is not mistaken for an
% argument token (which would raise "Illegal parameter number").
\newif\ifvscodeaccsupp
\IfFileExists{accsupp.sty}{\vscodeaccsupptrue}{\vscodeaccsuppfalse}
\ifvscodeaccsupp
  \usepackage{accsupp}
  \newcommand{\noncopynumber}[1]{\BeginAccSupp{ActualText={}}#1\EndAccSupp{}}
\else
  % accsupp unavailable: keep numbers visible, without copy protection.
  \newcommand{\noncopynumber}[1]{#1}
\fi

% Default Style
% ---
% Neutral fallback for code blocks whose language is not in the explicit map
% above. It applies the VS Code palette to keywords/strings/comments without
% forcing a specific grammar, so an unmapped language is no longer mis-colored
% with Java keywords. Pandoc still passes `language=...` per block when it
% recognizes the fence, so built-in listings languages keep full highlighting.

    keywordstyle=\color{vscode-keyword}\bfseries,
    commentstyle=\color{vscode-comment}\itshape,
    stringstyle=\color{vscode-string},
}
